# K-BigData 도메인 아키텍처

이 문서는 k-bigdata.kr 계열 서비스를 외부 홍보와 학생 내부 운영으로 분리하고, 도메인 간 링크 원칙을 유지하기 위한 기준입니다.

## 1. 외부 공개 · 학과/입시 홍보

| 도메인 | 역할 | 연결 원칙 |
|---|---|---|
| https://ai.k-bigdata.kr/ | 학과 홍보·입시 대표 허브 | 모든 외부 홍보 유입의 중심 |
| https://contest.k-bigdata.kr/ | 해당 연도 프로젝트 작품전시회 | ai와 portfolio로 연결 |
| https://portfolio.k-bigdata.kr/ | 역대 프로젝트·포트폴리오 아카이브 | ai와 contest로 연결 |
| https://prof.k-bigdata.kr/ | 교수 연구·교육·기술 콘텐츠 | ai 입학 허브와 portfolio로 연결 |
| https://alumni.k-bigdata.kr/ | 졸업생 네트워크·공개 취업/동문 정보 | 공개 필드와 개인정보 필드를 엄격히 분리 |
| 공식 학과 홈페이지 | 학교 공식 정보 | 외부 서비스의 최종 공식 출처 |

외부 홍보 URL은 원칙적으로 ai.k-bigdata.kr에서 목적별 세부 사이트로 이동시킵니다. contest, portfolio, prof는 독립 홍보 허브가 아니라 학과 홍보를 보강하는 전문 사이트입니다.

## 2. 학생 내부 운영

| 도메인 | 역할 |
|---|---|
| https://portal.k-bigdata.kr/ | 학생 통합 진입점 |
| https://ready.k-bigdata.kr/ | 취업 준비·포트폴리오 점검 |
| https://apply.k-bigdata.kr/ | 입사지원 현황 |
| https://room.k-bigdata.kr/ | 프로젝트실 예약 |
| https://help.k-bigdata.kr/ | 학과 요청·신고 |

내부 운영 서비스는 외부 홍보 사이트의 주요 메뉴·CTA·사이트맵에 넣지 않습니다. 학생은 portal을 통해 진입하는 것을 기본 동선으로 합니다.

내부 서비스에는 다음 원칙을 적용합니다.

- 모든 페이지에 noindex, nofollow, noarchive
- robots.txt에서 전체 크롤링 차단
- 개인정보/지원정보/예약자 정보는 공개 API 응답 최소화
- noindex는 인증이 아니므로 민감 기능은 서버 인증을 별도로 적용
- 새 운영 서비스는 먼저 portal에 등록하고 외부 홍보 사이트에는 직접 노출하지 않음

## 3. 공개 참고자료를 portal에서 사용하는 경우

portfolio, contest, prof처럼 공개 사이트라도 학생의 학습·프로젝트·진로에 직접 도움이 되면 portal에서 참고자료로 연결할 수 있습니다. 단, 카드에 '공개 참고자료'처럼 학생 운영 서비스와 다른 성격임을 표시합니다.

## 4. ipsi.k-bigdata.kr

ipsi.k-bigdata.kr은 서울강서캠퍼스 전체 학과 입시 허브로, 빅데이터소프트웨어공학과 전용 홍보 생태계와 별도 프로젝트로 취급합니다.

- ai.k-bigdata.kr의 상위 사이트로 사용하지 않음
- k-bigdata 외부 사이트의 공통 내비게이션에 넣지 않음
- 캠퍼스 전체 입시 홍보 목적이 유지될 때만 별도 운영

## 5. 모바일·PC 공통 UX 원칙

- 모바일 우선: 360px 이상에서 가로 스크롤 없이 핵심 기능 사용
- 주요 버튼/터치 영역 최소 44px 이상
- 모바일에서 긴 표는 카드 전환 또는 명확한 가로 스크롤 컨테이너 사용
- 내부 서비스는 빠른 기능 접근을 우선하고 장식성 Hero를 최소화
- 외부 홍보 사이트는 각 목적의 개성을 유지하되 학과명, 네이비/블루 계열, 버튼·링크 규칙은 일관되게 유지
- 외부 링크는 ↗ 또는 새 창 안내를 일관되게 제공

## 6. 새 서비스 추가 체크리스트

1. 외부 홍보인가, 학생 내부 운영인가?
2. 대표 진입점은 ai인가 portal인가?
3. 기존 서비스와 역할이 중복되지 않는가?
4. 개인정보가 공개 API나 정적 소스에 포함되지 않는가?
5. 모바일 360/390/430px, 태블릿 768px, PC 1280px 이상에서 동작하는가?
6. 외부 사이트라면 canonical/sitemap/robots/OG를 갖췄는가?
7. 내부 사이트라면 noindex/robots 차단과 필요한 서버 인증이 있는가?
8. 새 도메인을 추가하기보다 기존 사이트의 하위 기능으로 넣는 편이 낫지 않은가?
