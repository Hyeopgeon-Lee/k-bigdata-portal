### 로딩 실측

인앱 Chromium의 Navigation/Paint/Resource Timing 표본이며 Lighthouse 점수 또는 전체 사용자 평균이 아님. HTTP 캐시·네트워크·Apps Script 실행 시간에 영향을 받으므로 개선율로 일반화하지 않음.

브라우저 캐시 30분 상한·강제 갱신·날짜별 건수 Map은 소스와 자동 테스트로 검증. ScriptCache 실제 만료 시각 계측 및 대규모 부하 시험은 수행하지 않음. Safari/Firefox와 Android/iPhone 실기기는 이 환경에서 실행하지 않았으므로 전체 브라우저 검증 완료로 판정하지 않음.

초기 수동 동기화 한 차례는 장시간 자동 실행과 겹쳐 잠금 시간 초과가 발생했으며, 자동 실행 완료 후 후속 자동/수동 동기화 성공을 확인함. 포털 삭제 확인창은 자동 제어 도구가 멈춰 사용자가 직접 확인했고 이후 삭제 완료를 확인함. 두 상황 모두 기존 데이터를 초기화하지 않음.

이번 실행에서 `schedule-integration`, `schedule-registration`, `schedule-page` 테스트 모두 통과. 서버 내부 장애의 실제 강제 주입 대신 모의 서비스 오류 테스트와 브라우저 API 차단을 구분해 수행함.

## 구축 및 보안

- 기존 개인 계정의 기본 캘린더 사용. 별도 캘린더를 생성하지 않음.
- 소유자가 Google OAuth 권한을 직접 승인함. 스크립트의 캘린더 권한은 읽기 전용.
- Apps Script 전용 프로젝트 생성, 비공개 Sheets 자동 생성, 웹 앱 소유자 실행 및 익명 조회 배포.
- Drive 권한 메타데이터: `shared=false`, 소유자 권한 1개. 공개/도메인 공유 없음.
- Sheets 및 스크립트 시간대: Asia/Seoul.
- `syncDepartmentCalendar` 시간 기반 트리거 1개, 10분 간격. 실행 이력의 시간 기반 실행 성공 확인(20:39:43, 20:44:01).
- 공개 API 응답에서 메모, 장소, 이메일, 회의 링크, 원본 캘린더 식별자 없음 확인.
- 저장소에는 공개 조회용 `/exec` URL만 등록. 비공개 저장소 ID 및 인증정보는 등록하지 않음.
- 저장소 Code.gs 원문을 편집기에 재적용하고 정규화한 내용 길이 및 체크섬을 읽기 확인한 뒤 기존 배포를 버전 2로 갱신. URL 유지.
