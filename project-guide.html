PROJECT THEME GUIDE

기술이 아니라
문제에서 시작하세요

졸업작품은 새로운 기술을 보여주기 위한 결과물이 아니라, 실제 사용자가 겪는 기존 문제를 발견하고 소프트웨어 서비스로 해결하는 과정입니다.

주제 선정 시작하기 ↓선배 작품 살펴보기 ↗
01

CORE PRINCIPLE

“무엇을 만들까?”보다 “어떤 문제를 해결할까?”

기능이나 기술을 먼저 정하면 사용 이유가 약한 결과물이 되기 쉽습니다. 주변의 불편을 관찰하고, 누가 언제 어떤 어려움을 겪는지 확인한 뒤 해결 방법을 설계하세요.

6-STEP PROCESS

문제 발견부터 검증까지

거창한 아이디어보다 분명한 사용자와 검증 가능한 문제에서 시작합니다.

01

불편을 관찰하기

학교, 직장, 지역사회와 일상에서 반복되는 불편과 낭비를 기록합니다.

  • 반복적으로 시간이 걸리는 일
  • 수작업·메신저·엑셀에 의존하는 일
02

사용자를 구체화하기

‘모든 사람’이 아니라 실제로 문제를 겪는 사람과 상황을 구체적으로 정합니다.

  • 사용자는 누구인가?
  • 언제, 어디서 문제가 발생하는가?
03

기존 해결 방법 조사하기

현재 쓰는 서비스와 업무 방식을 살펴보고, 해결되지 않은 빈틈을 찾습니다.

  • 기존 서비스의 한계
  • 사용자가 포기하거나 우회하는 지점
04

핵심 문제 한 문장으로 정의하기

기능 목록이 아니라 누구의 어떤 문제를 왜 해결해야 하는지 작성합니다.

  • 문제의 원인과 영향
  • 해결 후 달라질 행동
05

작은 서비스로 구현하기

가장 중요한 문제를 해결하는 최소 기능부터 만들고 실제 사용 흐름을 완성합니다.

  • 핵심 기능 1~3개 선정
  • 처음부터 끝까지 동작하는 MVP
06

사용자에게 검증하기

실제 사용자에게 사용하게 하고 의견과 데이터를 바탕으로 개선합니다.

  • 문제가 실제로 줄었는가?
  • 다시 사용할 의향이 있는가?

THEME FORMULA

주제 정의 한 문장

[사용자]가 [상황]에서 겪는 [문제]를 해결하기 위해, [핵심 기능]을 제공하는 서비스를 구현한다.

예시 — 프로젝트실을 이용하는 학생이 빈 공간과 예약 현황을 알기 어려운 문제를 해결하기 위해, 실시간 예약 및 사용 현황 서비스를 구현한다.

좋은 주제인지 점검하기

  • 실제 사용자를 만날 수 있는가?
  • 문제를 관찰하거나 근거로 설명할 수 있는가?
  • 한 학기 안에 핵심 흐름을 구현할 수 있는가?
  • 사용 전후의 변화를 확인할 수 있는가?

기술 선택 원칙

  • AI·빅데이터가 꼭 필요한 이유가 있는가?
  • 기술 없이 더 단순하게 해결할 수는 없는가?
  • 개인정보와 편향 문제를 고려했는가?
  • 기술 설명보다 사용자 가치를 먼저 말할 수 있는가?
