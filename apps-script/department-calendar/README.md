# 학과 주요 일정 — 공개 등록 및 Google 캘린더 연동

포털의 **일정 등록**에서 누구나 로그인 없이 일정명·분류·날짜·시간을 입력할 수 있습니다.
소유자의 기본 캘린더에는 `(학과) [분류] 일정명`으로 저장하고, 포털에는 접두어와 분류 표시를 뺀 제목을 표시합니다.
입력 제목 앞의 `(학과)` 또는 오타 `(하과)`는 제거한 후 접두어를 한 번만 붙입니다.

## Google 캘린더 메모로 대상 학년 지정 (2026-10-20)

일정 제목은 기존처럼 `(학과) [프로젝트] 발표회` 또는 `(학과) [시험] 중간고사`로 등록합니다. 캘린더 **설명(메모)** 안에 다음 중 하나를 **독립된 한 줄**로 입력하세요.

```text
대상학년: 1학년
```

또는 `대상학년: 2학년`, `대상학년: 전체`로 입력합니다.

- 메모 안에 다른 문장이나 설명을 함께 적어도 됩니다. 단, 학년 선언은 별도 줄에 두세요.
- 메모에 정확한 `대상학년:` 값이 있다면 **제목의 `[1학년]` / `[2학년]` 태그보다 우선** 적용됩니다.
- 학년 선언이 없거나 인식할 수 없는 값이면 기존 제목 태그로 판별하고, 그것도 없으면 **전체 학년**으로 처리합니다.
- `대상학년: 전체`는 기존 제목 태그가 있어도 전체 학년으로 설정합니다.
- 비공개 일정이거나 제목이 `(학과)`로 시작하지 않는 일정은 메모를 읽지 않습니다.
- **메모 원문은 절대로 공개 스프레드시트, API 응답, 브라우저 캐시에 저장하지 않습니다.** 오직 `"1"`, `"2"`, `"all"` 값만 사용합니다.
- **적용 단계:** GitHub 수정만으로 Google Apps Script 운영 웹 앱이 바뀌지 않습니다. 기존 Apps Script 편집기에서 이 저장소의 `Code.gs`를 적용한 뒤 **배포 → 배포 관리 → 기존 웹 앱 수정 → 새 버전 배포**를 진행해야 합니다. `syncDepartmentCalendar()`를 한 번 실행하여 기존 데이터를 반영하거나 기존 10분 동기화를 기다립니다. `setupDepartmentCalendar()` 재실행은 불필요합니다.
- 기존 웹 앱의 `/exec` 주소는 유지하세요. `PublicRegistration.gs`, 캘린더 원본 일정·일정 삭제 정책은 변경할 필요가 없습니다.

## 학년별 일정(2차 개선)

- 포털의 **일정 등록 → 대상 학년**에서 `전체 학년 / 1학년 / 2학년`을 선택합니다.
- 기존 Google Apps Script 웹 앱의 버전이 이전 버전이어도 포털은 등록 제목 앞에 `[1학년]` 또는 `[2학년]` 태그를 넣어 학년 구분을 유지합니다. 기존 API가 태그를 그대로 내보내더라도 포털 화면이 태그를 해석해 정상 표시합니다.
- 최신 Apps Script를 배포하면 `targetGrade` 필드를 `"all" / "1" / "2"`로 직접 공개합니다. 과거 일정은 `"all"`로 취급합니다.
- Google 캘린더에서 직접 만드는 일정은 제목 태그보다 **메모 `대상학년: 1학년` 또는 `대상학년: 2학년`** 사용을 권장합니다. 기존 제목의 학년 태그도 계속 인식합니다.
- 포털의 일정 목록에서는 학년 필터가 적용되어도 **전체 학년** 일정은 함께 표시됩니다.
- GitHub Pages 배포만으로 Apps Script 스크립트의 새로운 공개 필드는 배포되지 않습니다. 새 필드를 활성화하려면 기존 Apps Script 프로젝트의 `Code.gs`와 `PublicRegistration.gs`를 갱신하고 **기존 웹 앱 배포의 새 버전**을 게시해야 합니다. 기존 `/exec` URL은 유지하세요. `setupDepartmentCalendar()`를 다시 실행할 필요는 없습니다.
- 동기화 시 비공개 스프레드시트 열이 하나 추가됩니다(`targetGrade`). 기존 공개 일정은 자동으로 전체 학년으로 처리되며, Calendar 개인 일정 공개 차단·등록 출처 태그·삭제 제한은 그대로 유지됩니다.

## 운영 설정

- 기존 Apps Script 프로젝트에 `Code.gs`, `PublicRegistration.gs`, `appsscript.json`을 적용합니다.
- 시간대는 Asia/Seoul입니다. 기존 프로젝트는 `syncDepartmentCalendar()`를 실행하고 소유자가 추가 캘린더 권한을 직접 승인합니다.
- 공개 등록에는 CalendarApp 쓰기 권한이 필요하므로 매니페스트에 `calendar` 범위를 명시합니다. Sheets·트리거 권한은 유지합니다.
- **GitHub Pages 자동 배포와 Apps Script 웹 앱 배포는 별개입니다.** GitHub 수정 후 Apps Script 프로젝트의 `Code.gs`, `PublicRegistration.gs`를 모두 갱신하고 **배포 관리 → 기존 웹 앱 수정 → 새 버전 → 배포**해야 삭제 API가 운영됩니다. 실행 사용자는 소유자, 접근은 모든 사용자이며 기존 `/exec` URL을 유지합니다.
- 신규 구축에서만 `setupDepartmentCalendar()`를 실행합니다. Sheets 재사용과 10분 트리거 중복 방지를 지원합니다.
- `data/schedule-config.js`에는 공개 웹 앱 URL만 저장합니다. 개인 캘린더 ID·Sheets ID·인증정보는 저장하지 않습니다.

## 공개와 개인정보

- 개인 캘린더 전체와 원본 Sheets는 비공개입니다. 학생에게 캘린더 접근 권한을 주지 않습니다.
- `doGet`은 정확히 `(학과)`로 시작하는 공개 가능 일정만 조회합니다. 해당 일정의 설명에서 대상학년 한 줄만 추출하며, 설명 원문·장소·참석자·이메일·회의 링크는 제외합니다.
- `doPost`는 새 일정 등록과 **포털에서 등록한 일정에 한정된 공개 삭제**를 지원합니다. 익명 사용자는 수정할 수 없습니다.
- 포털 등록 시 서버가 Google CalendarEvent에 `kbigdata_portal_registration=portal-v1` 태그를 부여합니다. 비공개 Sheet에도 `source=portal`을 기록하고, 삭제 시 Sheet의 출처와 캘린더 원본 태그를 **모두 재검증**합니다.
- **Google 캘린더에서 직접 생성한 `(학과)` 일정은 화면에 삭제 버튼이 없고, 임의 POST로도 삭제할 수 없습니다.**
- 이전에 등록된 일정 가운데 포털 출처를 검증할 수 없는 항목은 원본 보호를 위해 삭제 불가로 처리합니다. 소유자가 캘린더에서 정리할 수 있습니다.
- 캘린더에서 직접 만든 일정의 수정·삭제는 소유자가 Google 캘린더에서 수행합니다. 접두어 제거도 다음 동기화에서 공개 해제됩니다.
- 비공개/기밀로 지정한 일정은 접두어가 있어도 공개하지 않습니다.
- 동기화 실패 시 API는 오류와 빈 목록만 반환합니다.

## 등록 검증과 사용 범위

- 일정명 1~100자, 허용 분류, 날짜와 시간을 서버에서 검증합니다.
- 오늘부터 18개월 이내, 최대 31일의 일정을 등록할 수 있습니다. 입력 종료일은 포함하며 종일 일정은 캘린더의 배타적 종료일로 변환합니다.
- 익명 등록의 과도한 사용을 제한하기 위해 한국시간 기준 전체 공개 등록을 하루 50건으로 제한합니다. 캘린더에서 직접 등록한 일정은 이 한도에 포함하지 않습니다.
- 무작위 요청 식별자와 잠금으로 중복 생성을 방지하고, 타임아웃 뒤 같은 내용 재시도에는 같은 식별자를 사용합니다.
- 익명 등록은 등록자 신원을 보증하지 않습니다. 허위 일정은 소유자가 캘린더에서 삭제할 수 있습니다.
- 등록·삭제 결과 HTML은 내부 Google Calendar ID 없이 성공 여부와 오류만 반환하며, 메시지는 운영 포털 도메인에만 전달합니다. 클라이언트는 응답 출처와 요청 식별자를 검사합니다.
- 등록·삭제 후 즉시 동기화를 시도하며 기존 10분 자동 트리거도 유지합니다. 동기화 조회 범위는 현재 월 기준 과거 6개월~미래 18개월입니다.
- 공개 삭제는 확인 창을 거친 뒤 수행합니다. 누구나 삭제할 수 있으므로 포털 등록 일정은 익명 사용자의 삭제 가능성을 고려해 운영해 주세요.

## 속도 최적화 및 캐시 정책

- 포털 브라우저는 **공개 일정 데이터만** 로컬 저장소에 최대 30분간 보관합니다. 재방문 시 즉시 표시하되, 페이지마다 Apps Script에서 최신 데이터를 다시 조회합니다.
- Google 캘린더 비공개 원본, 내부 Calendar ID, 참석자, 설명, 연락처, 인증정보는 캐시에 포함하지 않습니다.
- API가 실패하거나 동기화 결과가 유효하지 않으면 캐시를 폐기하고 목록을 비워 기존 비공개 보호 정책을 유지합니다.
- 등록·삭제에 성공하면 브라우저 캐시를 삭제하고 강제 재조회합니다. 삭제된 항목은 재조회 전에도 화면에서 즉시 제거합니다.
- Apps Script는 **공개용 필드만 가공한 응답**을 ScriptCache에 최대 90초 동안 저장하고 반복 시트 조회를 줄입니다. 25,000자 초과 응답이나 캐시 장애는 시트 직접 읽기로 폴백합니다.
- 캘린더 동기화 완료 또는 실패 시 Apps Script 캐시를 무효화합니다. Google Calendar 직접 등록한 일정의 삭제 금지 정책은 동일하게 적용됩니다.
- 실제 운영에 이 서버 캐시를 적용하려면 Apps Script의 `Code.gs` 파일을 갱신하고 **기존 웹 앱 새 버전을 배포**해야 합니다. GitHub Pages의 자동 배포만으로는 적용되지 않습니다.
