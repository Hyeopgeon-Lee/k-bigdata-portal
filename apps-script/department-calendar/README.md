# 학과 주요 일정 — 공개 등록 및 Google 캘린더 연동

포털의 **일정 등록**에서 누구나 로그인 없이 일정명·분류·날짜·시간을 입력할 수 있습니다.
소유자의 기본 캘린더에는 `(학과) [분류] 일정명`으로 저장하고, 포털에는 접두어와 분류 표시를 뺀 제목을 표시합니다.
입력 제목 앞의 `(학과)` 또는 오타 `(하과)`는 제거한 후 접두어를 한 번만 붙입니다.

## 운영 설정

- 기존 Apps Script 프로젝트에 `Code.gs`, `PublicRegistration.gs`, `appsscript.json`을 적용합니다.
- 시간대는 Asia/Seoul입니다. 기존 프로젝트는 `syncDepartmentCalendar()`를 실행하고 소유자가 추가 캘린더 권한을 직접 승인합니다.
- 공개 등록에는 CalendarApp 쓰기 권한이 필요하므로 매니페스트에 `calendar` 범위를 명시합니다. Sheets·트리거 권한은 유지합니다.
- 기존 웹 앱을 새 버전으로 갱신합니다. 실행 사용자는 소유자, 접근은 모든 사용자입니다. 기존 `/exec` URL을 유지합니다.
- 신규 구축에서만 `setupDepartmentCalendar()`를 실행합니다. Sheets 재사용과 10분 트리거 중복 방지를 지원합니다.
- `data/schedule-config.js`에는 공개 웹 앱 URL만 저장합니다. 개인 캘린더 ID·Sheets ID·인증정보는 저장하지 않습니다.

## 공개와 개인정보

- 개인 캘린더 전체와 원본 Sheets는 비공개입니다. 학생에게 캘린더 접근 권한을 주지 않습니다.
- `doGet`은 정확히 `(학과)`로 시작하는 공개 가능 일정만 조회합니다. 설명·장소·참석자·이메일·회의 링크는 제외합니다.
- `doPost`는 새 일정 등록만 허용합니다. 기존 일정의 외부 수정·삭제 기능은 없습니다.
- 기존 일정 수정·삭제는 소유자가 Google 캘린더에서 수행합니다. 접두어 제거도 다음 동기화에서 공개 해제됩니다.
- 비공개/기밀로 지정한 일정은 접두어가 있어도 공개하지 않습니다.
- 동기화 실패 시 API는 오류와 빈 목록만 반환합니다.

## 등록 검증과 사용 범위

- 일정명 1~100자, 허용 분류, 날짜와 시간을 서버에서 검증합니다.
- 오늘부터 18개월 이내, 최대 31일의 일정을 등록할 수 있습니다. 입력 종료일은 포함하며 종일 일정은 캘린더의 배타적 종료일로 변환합니다.
- 익명 등록의 과도한 사용을 제한하기 위해 한국시간 기준 전체 공개 등록을 하루 50건으로 제한합니다. 캘린더에서 직접 등록한 일정은 이 한도에 포함하지 않습니다.
- 무작위 요청 식별자와 잠금으로 중복 생성을 방지하고, 타임아웃 뒤 같은 내용 재시도에는 같은 식별자를 사용합니다.
- 익명 등록은 등록자 신원을 보증하지 않습니다. 허위 일정은 소유자가 캘린더에서 삭제할 수 있습니다.
- 결과 HTML은 내부 ID 없이 성공 여부와 오류만 반환하며, 메시지는 운영 포털 도메인에만 전달합니다. 클라이언트는 응답 출처와 요청 식별자를 검사합니다.
- 등록 후 즉시 동기화를 시도하며 기존 10분 자동 트리거도 유지합니다. 동기화 조회 범위는 현재 월 기준 과거 6개월~미래 18개월입니다.

## 검증

`node tests/schedule-registration.test.mjs`

`node tests/schedule-integration.test.mjs`

`node tests/schedule-page.test.mjs`

실제 포털 제출 → 소유자 캘린더 저장 → 접두어 없는 포털 표시 순으로 확인하고 테스트 일정을 삭제합니다.
로컬 미리보기에서는 운영 도메인으로 제한한 결과 메시지를 받을 수 없으므로 실제 등록 결과는 운영 포털에서 검증합니다.
