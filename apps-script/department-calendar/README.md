# 학과 주요 일정 — Google 캘린더 자동 연동

개인 Google 캘린더 전체를 공개하지 않고 **제목이 \`(학과)\`로 시작하는 일정만** 포털에 표시합니다. Google Calendar 계정은 포털에 직접 로그인하지 않습니다.

## 동작 방식

1. 캘린더 소유자가 자신의 기본 Google 캘린더에 \`(학과) 발표회\`와 같이 일정을 등록합니다.
2. 계정 소유자가 직접 승인한 Google Apps Script가 약 **10분 간격**으로 기본 캘린더를 읽고 \`(학과)\` 일정만 추립니다.
3. Script에서 만든 **비공개 Google Sheets**에는 ID·제목·분류·날짜·시각만 저장합니다.
4. 웹 앱 URL은 **읽기 전용**으로 공개하고, 포털 \`schedule.html\`은 공개 목록만 불러옵니다.
5. 일정 수정·삭제, \`(학과)\` 접두어 삭제도 이후 동기화에서 반영됩니다.

## 1. 소유자 1회 설정 (반드시 Google 계정에서 직접 수행)

현재 ChatGPT의 Google Calendar 연결과 Apps Script 배포 권한은 별개입니다. 이 저장소의 GitHub 수정만으로 Google 계정의 캘린더를 읽을 수 없습니다.

1. **[Google Apps Script](https://script.google.com/home/projects/create)** 에서 새 프로젝트를 만듭니다.
2. 이 저장소의 [Code.gs](./Code.gs)를 복사하여 Apps Script 편집기의 \`Code.gs\` 전체를 교체합니다.
3. **프로젝트 설정 → '앱 스크립트 매니페스트 파일 표시'** 를 켠 뒤 [appsscript.json](./appsscript.json)의 내용을 매니페스트에 복사합니다. 시간대를 **Asia/Seoul** 로 유지합니다.
4. 상단 함수 선택에서 **setupDepartmentCalendar** 를 선택하고 **실행**합니다.
5. Google 계정에서 **캘린더 읽기, 스프레드시트 생성·쓰기, 트리거 관리** 등에 필요한 권한을 직접 승인합니다.
6. 성공하면 \`학과 주요 일정 - 포털 공개 목록 (비공개)\` Google Sheet가 자동 생성되고 10분마다 동기화 트리거가 설정됩니다. 새로 만든 Sheet는 **공유하거나 웹에 게시하지 마세요.**
7. 오른쪽 위 **배포 → 새 배포 → 웹 앱**을 선택합니다. **실행 사용자: 나**, **액세스 권한: 모든 사용자(Anyone)** 로 배포합니다. 도메인 관리 정책상 '모든 사용자' 배포를 허용하지 않는다면 대체 인증 방식이 필요합니다.
8. 배포 후 표시되는 **\`https://script.google.com/macros/s/.../exec\`** URL을 복사합니다.
9. 포털 저장소의 [data/schedule-config.js](../../data/schedule-config.js) \`SCHEDULE_API_URL\`에 **해당 URL만** 입력하고 main 브랜치에 저장합니다. GitHub Pages 자동 배포 후 [학과 주요 일정](https://portal.k-bigdata.kr/schedule.html)을 확인합니다.

**포털 또는 저장소에 입력하면 안 되는 것:** Google 비밀번호·OAuth 토큰·개인 캘린더 ID·Google Sheets ID·Script Properties 값.

## 2. 일정 작성 규칙

| 캘린더 일정 제목 | 포털 공개 | 분류 |
|---|---|---|
| \`(학과) 졸업작품 발표\` | 공개 | 프로젝트(자동 분류) |
| \`(학과) [시험] 중간고사\` | 공개 | 시험 |
| \`(학과) [취업] 기업 채용설명회\` | 공개 | 취업 |
| \`개인 일정\` | 비공개 | - |
| \`학과 중간고사\` | 비공개 | - |
| \`개인 (학과) 회의\` | 비공개 | - |

선택 가능한 분류: **학사, 시험, 프로젝트, 취업, 자격증, 행사**. 분류를 생략하면 제목 키워드로 분류하며 기본값은 행사입니다. **비공개로 설정한 일정은 제목에 \`(학과)\`가 있어도 게시되지 않습니다.**

반드시 학생에게 공개할 수 있는 제목만 사용하세요. \`(학과)\` 일정은 공개 웹 페이지에서 누구나 볼 수 있으므로 민감한 개인 정보나 내부 회의 제목은 사용하지 마세요. 장소·설명·첨부파일·참석자·이메일·회의 링크는 자동 공개되지 않습니다.

## 3. 확인 및 오류 대응

- \`schedule.html\`에서 **연동 준비 중**: \`SCHEDULE_API_URL\`을 아직 등록하지 않았습니다.
- **일정 가져오기 실패**: 웹 앱 URL, '나로 실행' 및 '모든 사용자' 액세스, 최초 \`setupDepartmentCalendar\` 성공 여부를 확인합니다.
- 일정 추가 후 바로 보이지 않음: 10분 동기화 이후 새로고침합니다. 트리거 실행은 초 단위로 정확하지 않을 수 있습니다.
- 일부 일정 누락: 제목이 정확히 \`(학과)\`로 시작하는지, 비공개 일정인지, 현재 월을 기준으로 **6개월 전부터 18개월 후** 범위인지 확인합니다.
- 배포 후 Code.gs 수정: **배포 → 배포 관리 → 수정 → 새 버전**을 선택해야 변경된 웹 앱 코드가 적용됩니다.
- 테스트: \`(학과) [시험] 연동 시험\` 일정 한 개를 만든 후 동기화 실행 → 포털 확인 → 캘린더 일정 삭제 → 동기화 실행 → 포털에서 사라지는지 확인합니다.

### 보안 경계

- 공개 웹 앱 \`doGet\`은 **읽기 전용**이며 \`doPost\`는 없습니다.
- 읽기 응답에는 제목, 분류, 날짜, 시간, 식별 ID만 포함합니다.
- 기본 캘린더 외 다른 캘린더는 조회하지 않습니다.
- 포털은 공개 일정만 표시하며, Google Calendar 인증정보는 받지 않습니다.
- Google Sheet 및 Apps Script 프로젝트는 관리자 계정에서 비공개로 관리합니다.
- 매니페스트는 캘린더 **읽기 전용**, Sheets 생성·읽기·쓰기, 트리거 관리 권한을 명시합니다. 캘린더 쓰기 권한은 요청하지 않습니다.
- 기본 캘린더만 사용하며 `CALENDAR_ID` 속성으로 다른 캘린더를 지정할 수 없습니다.
- 날짜·시각은 Sheets에서 텍스트로 저장합니다. 동기화 실패 후에는 공개 API가 이전 목록 대신 오류와 빈 목록을 반환합니다.
- 포털은 10분마다 다시 조회하며 원격 응답에서 장소·설명·링크를 받더라도 표시하지 않습니다.
- `node tests/schedule-integration.test.mjs`는 모의 Google 서비스로 재설정 시 Sheet 재사용·트리거 중복 방지·등록·수정·이동·삭제·접두어 제거·반복 식별자·실패 차단을 검증합니다. 실제 계정/배포 검증은 별도로 수행해야 합니다.
