# 실기 문제 모바일 가독성 전수 검수 (2026-10-05)

## 검수 범위

정보처리기사·정보처리산업기사 실기 문제은행의 현재 386문제를 전수 검사했다. 모바일에서 실제 학습을 방해하는 요소를 기준으로 문제문 길이, 코드 줄 수, 코드 한 줄 길이, SQL 폭, 표, 정답 길이, 풀이 단계 길이를 검사했다.

## 전문가 관점

- 모바일 UX: 320~430px 폭에서 한 손 스크롤과 화면 점유율을 우선했다.
- 학습 UX: 문제 → 코드 추적 → 답 입력 → 60초 후 풀이 확인 흐름이 끊기지 않는지 확인했다.
- 프론트엔드: fixed/sticky 영역, safe-area, visualViewport, 가로·세로 스크롤 충돌을 검토했다.
- 접근성: 44px 이상 터치 영역, dialog 닫기, 키보드 접근, aria 연결을 유지했다.
- 문제은행 QA: 코드 의미와 정답을 바꾸지 않는 표현·포맷 변경만 허용했다.

## 전수 검사 결과

초기 검사에서 모바일 주의 문항은 32개였다.

- 코드 16줄 이상: 20문제
- 한 줄 80자 이상 코드: 7문제
- 문제문 80자 이상: 3문제
- 정답 80자 이상: 3문제
- 일부 문항은 두 기준에 동시에 해당한다.

표 문제는 최대 3열로 현재 구조에서 독립 가로 스크롤만으로 충분했다. 긴 정답은 결과 영역의 pre-wrap이 이미 적용되어 추가 데이터 수정이 필요하지 않았다.

## 구현

1. 문제 풀이 중 중복 상단 헤더를 제거해 모바일 세로 공간을 확보했다.
2. 긴 문제문은 80자 이상일 때 문장 단위로 시각적 줄바꿈한다.
3. 긴 코드(16줄 이상 또는 원본 한 줄 72자 이상)는 인라인 영역 높이를 52svh로 제한한다.
4. 긴 코드에는 모바일에서 '코드 크게 보기' 버튼을 제공하고 전체 화면 dialog로 읽을 수 있게 했다.
5. SQL 표시기는 FROM/WHERE/GROUP BY뿐 아니라 plain JOIN과 ON도 줄바꿈한다.
6. R-JAVA-0032와 R-C-0014의 과도하게 긴 한 줄 코드는 동작을 바꾸지 않고 들여쓰기와 줄바꿈만 정리했다.
7. SQL은 모바일에서 pre-wrap을 사용하고 C/Java/Python은 원래 코드 구조를 유지하며 필요 시 가로 스크롤한다.
8. 답 입력 바로가기와 하단 고정 풀이 동선은 유지한다.

## 자동 회귀 검사

tests/practical-mobile-readability.test.mjs를 추가했다. 문제 수와 ID 고유성, 비-SQL 80자 이상 코드 라인 금지, 최대 원본 코드 라인 120자 제한, 문제문 최대 길이, 전체화면 코드 reader, 긴 코드 높이 제한, SQL JOIN/ON 포맷, 긴 문장 표시 로직이 이후 변경에서 사라지지 않는지 검사한다.

문제 추가 시 이 테스트를 함께 실행하면 모바일 가독성이 다시 악화되는 것을 조기에 발견할 수 있다.
